# Provisional Phase 5 interface — NOT frozen, NOT organizer contract

Source: Master TZ §14; organizer schemas unavailable. Separate unmerged PR #1 proposes schemas; see draft CR and issue #3. Do not treat this file as contract approval or use it to supersede PR #1's proposed freeze.

`Environment.reset(path, config)` requires a directory literally named `public` reached without symlinks. Config is exactly `{mode: "CLOSED_EVAL", max_steps: 1..100, cursor_key: bytes}`; key must be at least 32 bytes supplied by the caller. Reset returns public company, policy, opening balances, calendar, budget and mode. Reset fails closed on malformed/missing inputs; it does not emit paths to policy. It requires Master TZ §8.2's listed files except optional document_links, with either JSON-array or JSONL accounts, and object or array balances/calendar. FX rows use `fx_rate_id` or the composite described below. These conventions have not been approved as official schemas.

`step({tool, args, action_id?})` returns observation/result, reward=0, terminated, truncated, info={}. Calls including invalid submit consume a step, except a valid submit; last charged step truncates, and submit after truncation is refused. This is provisional because organizer budget behavior is unknown. Accepted actions: list_records(table, cursor?, limit?, filters?), get_record(table, id), get_document(doc_id), submit(findings). Filters use exact equality on a per-table allowlist and IDs sort lexicographically. Cursor handles are HMAC-derived over public snapshot, filters and last key; a per-episode map rejects unknown or foreign cursors. Determinism requires the same caller-supplied secret and action history. Shared-process callers can inspect the key/map: use process isolation in a future harness. CLI key is fixed and public: it is NOT authentication against a malicious policy.

Provisional findings require exactly type, affected_ids, amount_minor, currency, evidence_ids. No semantic validity, evidence reachability, ID namespace or scoring is asserted. PR #1's `finding.schema.json` instead requires schema_version, claimed_amount and typed IDs, so integration is blocked pending review. `calc` is omitted until required by approved contract; PR #1 proposes it, making reconciliation necessary. OPEN_DEV and finalize are intentionally absent. Static limits are in `env/budget.py`. The loader detects some forbidden keys but does not prove input free of secrets or hidden labels; producer validation and process/filesystem isolation remain required.

## Follow-up: Phase 4 snapshot interoperability (2026-11-21)

The loader additionally accepts `accounts.jsonl` in lieu of `accounts.json` (both present is an error), and accepts either object or array for opening balances and period calendar. Phase 4 snapshot `e7407843f9daf4f133ad7d1f032969713f7dd54e` emits JSONL accounts and object-valued balances/calendar. It has FX rows keyed by `(pair,effective_date)` instead of `fx_rate_id`: their provisional `get_record` ID is `pair@effective_date`; rows are sorted and paginated on this string. Both components must be nonempty strings without `@`. This is an internal compatibility convention, not a change to either upstream schema and not organizer-approved. Duplicate keys are rejected. File reads additionally reject regular files with multiple hard links, but this is not a substitute for process isolation or trust in the public-file producer.

Five real public outputs (three L1 and two L2) from that snapshot were smoke-tested using `python3 -m tools.phase05_public_smoke /path/to/public` (see follow-up report). The snapshot itself was separately tested in an isolated temporary source export. Its tool/finding schemas are not the same as PR #1; neither was merged or declared authoritative here. The sample and public-file checks do not prove complete schema coverage, hidden-data safety, truth accuracy or official adapter compatibility.
