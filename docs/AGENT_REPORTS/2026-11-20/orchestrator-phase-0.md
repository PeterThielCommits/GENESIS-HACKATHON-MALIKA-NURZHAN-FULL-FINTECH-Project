## Judgement calls I made (all recorded as decisions)

* **D-0001** — no organizer contract exists, so nothing may be labelled `CONFIRMED`. I did not
  copy any third-party repository, even where it looked complete.
* **D-0002** — internal checks stay `official: false`; the schema enforces `const: false`, so a
  future agent cannot flip it in a data file without failing the build.
* **D-0015** — unimplemented work is reported as `BLOCKED` with the phase that will implement
  it. I refused to let planned checks count as passes; a green suite that hides 28 unbuilt
  checks would be worse than a red one.
* **D-0019** — a stdlib JSON-Schema subset validator, and it *fails* when a schema uses a
  keyword outside the subset. Silently ignoring a keyword would make the fixtures meaningless.
* **D-0011/D-0012** — `CLOSED_EVAL` is the default and process separation is described as what
  it is: not a sandbox. Three boundaries in the threat model are marked "NOT ENABLED" today.

## Mistakes I made and fixed (kept so they are not repeated)

* The first claim scanner flagged its own documentation while missing nothing real; the fix was
  a negation-aware rule plus an explicit, reviewed exemption marker limited to `tests/phase0/`.
* A test read `REQ-DATA-022` and matched the nonexistent assumption `A-022`; ids now require a
  non-letter boundary.
* `docs/PHASE_REPORTS/PHASE-00.json` was hand-edited once and immediately drifted; it is now
  generated by `tools/verify.py` from its own summary and a test fails if the two disagree.
* Failing tests were initially reported as release blockers (exit 4), which would have made the
  exit code meaningless; blockers are now only false official claims and committed secrets.
