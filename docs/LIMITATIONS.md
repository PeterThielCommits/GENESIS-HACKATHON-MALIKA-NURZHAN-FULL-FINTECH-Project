# Known Limitations (Release v1.0.2 — Phases 0–17 Complete)

Honest engineering disclosure per Master TZ Principle `P-012` ("Честность сильнее декоративной сложности") and Section 27 (`R-01..R-24`).

1. **L1 — Benchmark Scope vs Real ERP Systems:** TwinLedger is a 100% synthetic research and hackathon benchmark covering four documented accounting anomaly classes (`DUPLICATE_PAYMENT`, `PARTIAL_PAYMENT_ALLOCATION`, `FX_RATE_MISMATCH`, `PERIOD_CUTOFF`) and 16 clean distractor families (`D-DUP/PART/FX/CUT-01..04`). It is not a real statutory accounting or audit product.
2. **L2 — Host-Dependent OS Sandbox Capabilities (`R-09`):**
   - On Linux hosts supporting unprivileged user, mount, and network namespaces plus `seccomp-BPF` (live-verified on `x86_64` Linux 6.1+ and inside the `docker-offline` CI job), `harness/sandbox.py` + `harness/ns_launcher.py` enforce `profile_id = "linux-kernel-ns-seccomp-v1"` (`is_full_os_sandbox: true`): private `MS_REC|MS_PRIVATE` mount namespaces overmounting `episodes/` and `sealed/` with read-only `tmpfs`, read-only `tmpfs` policy `cwd` (`EROFS`), isolated network namespace, `PR_SET_NO_NEW_PRIVS`, and `seccomp-BPF` blocking `socket`, `mount`, `umount2`, `pivot_root`, `ptrace`, `process_vm_readv`, and `process_vm_writev`.
   - On non-Linux hosts (macOS/Windows) or restricted kernels where `probe_kernel_sandbox_capabilities()` detects unavailable namespace/seccomp support, `detect_security_profile()` automatically and honestly degrades to `posix-subprocess-isolated-v1` (`is_full_os_sandbox: false`, listing exact `unavailable_controls`) unless run inside `docker run --network=none --read-only --cap-drop ALL`.
3. **L3 — Commit-Reveal vs Semantic Correctness (`R-10`):** Cryptographic commit-reveal (`SHA256("twinledger-truth-v1:" || salt || ":" || canonical_truth)`) proves post-commitment immutability only, NOT semantic truth validity. Semantic truth validity is enforced separately via Stage-1 public-only `verifier.discover` + Stage-2 `scoring/crosscheck.py` (`semantic_truth_verification: VERIFIED` in `scoring/scorer_cli.py`). Checked-in `dev`/`train` fixtures use deterministic `TEST_FIXTURE` salts for clean-clone reproducibility, while `python3 -m seal.cli rekey-production` (`seal/rekey.py`) seals private competition splits with 256-bit `secrets.token_hex(32)` `PRODUCTION_SECRET` salts.
4. **L4 — Side-Channel & Shortcut Audit Bounds (`R-06`, `R-12`):**
   - Within-table L2 Logistic Regression metadata auditing (`judge/shortcut_audit.py`) verifies `macro_ROC_AUC <= 0.55` across surface metadata features, confirming absence of trivial generator stamps while recognizing that real accounting structure legitimately distinguishes anomaly classes once domain relations are joined.
   - The 10-channel canary fuzzer inspects `observation`, `tool_errors`, `info`, `policy_logs`, `tracebacks`, `filenames_and_paths`, `cursor_payloads`, `response_sizes`, `environment_variables` and `policy_stdio_pipe`, applying 9 encoding transforms (exact/casefold/hex-lower/hex-upper/base64/base64-urlsafe/URL-percent/NFC/NFKC). Measured: 0 hits (`canary_fuzz_report.json`); both enumerations are source-checked by `tools/verify_doc_claims.py`, so this page cannot silently drift from `judge/canary_fuzzer.py`.
   - Warmed-up interleaved timing equivalence (`tost_ci90_diff_us` within practical margin) bounds local Python IPC timing differences; it does not prove absence of hardware/microarchitectural cache side channels.
5. **L5 — AutoHacker & Mutation Score Interpretation (`R-13`, `R-24`):**
   - AutoHacker (`arena/autohacker.py`) demonstrates positive out-of-sample sensitivity on seed-grouped `HELDOUT` episodes over an interpretable `AuditorParams` space; it does not prove absence of all conceivable exploit strategies.
   - Achieving `26/26` (100%) killed mutants in `judge/mutation_suite.py` verifies test sensitivity against the 26 declared matcher/reward defect classes, not mathematical absence of all bugs.
6. **L6 — Internal Verification Pass Rate vs Official Jury Score (`R-01`, `R-20`, `R-24`):** TwinLedger implements both the provisional Master TZ v3.0 rubricator (`RC-001..RC-012`) and the Official Genesis FinTech 2026-11-20 mirror checks (`tests/official/*`, `judge_adapter.py`). Internal `PASS` (100% of internal gates) is never claimed as an official organiser jury score.
7. **L7 — Episode Input Bounds (`D-10-03`, review remediation 2026-11-21):** Every episode-supplied file read (`env/loader.py`, `adapter/official_env.py`, `scoring/official_scorer.py`, `verifier/public_loader.py`) is hard-capped at `contracts.loader.MAX_INPUT_FILE_BYTES = 16 MiB` per file and `MAX_INPUT_ROWS = 100_000` rows per file, with a fixed bounded `LIMIT`-class error on overflow. Measured legitimate workload across every checked-in episode: ≤26.9 KiB per generated public file and ≤146 rows in any one table — the caps leave 609x/685x headroom, so official checks (`C01..C20`, `D01..D20`, `P01..P20`, `M01..M12`) are unaffected. Consequently, a hypothetical legitimate dataset larger than these caps would be rejected by design; raise the constants in `contracts/loader.py` (and re-run `tests/env/test_loader_order_and_bounds.py`) if an official task ever ships bigger fixtures. Also note: `env/loader.py` now preserves file row order verbatim (README "Canonical Tables"), matching the adapter — pagination cursors page over rows exactly as stored.
8. **L8 — The Evidence Freeze Is Per-Commit, and the Archive Is a Snapshot (`D-17-02`):** the post-release evidence freeze (`docs/EVIDENCE/evidence_freeze.json`) pins the SHA-256 of every tracked file **at the commit it was written for**. That is exactly what makes "the release is restorable" true, but it also means the archive is a *release snapshot*: any later commit changes the tree, so `make evidence-verify` fails until `make evidence-write` is re-run in the same commit. This is a deliberate, visible act (a silent drift would be the bug), not a defect — but it does mean the archive of tag `v1.0.2` describes tag `v1.0.2`, and a later patch release needs its own archive. The companion archive (`docs/EVIDENCE/phase-17-release-evidence-2026-11-22.json`) records the *release-run* verdicts and the decision register as of the release; it is checked for honesty and self-consistency on every commit, and for exact equality with a fresh measurement only at release time (`python3 tools/release_evidence.py --verify --strict`). The two archive files are excluded from the hashed surface, because an archive cannot contain its own digest; their integrity is the commit itself.
9. **L9 — The Docker *Image Build* Is CI-Authoritative (`D-16-04`):** no container runtime and no registry access exist on the execution host (probed 2026-11-22: `docker`, `podman`, `buildah`, `nerdctl`, `ctr`, `runc`, `containerd` — none; `registry-1.docker.io`, `ghcr.io`, `quay.io` — unreachable), so `docker build` cannot run locally: the base image cannot be pulled. The image build and the hardened offline run (`--network=none --read-only --cap-drop ALL --pids-limit --ulimit fsize`) are proven by the CI `docker-offline` job, not locally.
   - What *is* proven locally, and is **not** a container build: `tools/container_local_check.py` materialises the image the way `docker build` would — the build context with `.dockerignore` applied through Docker's own path semantics, the `compileall` step, the report directories — and then runs the container's own command (`make verify`) inside an unprivileged user+mount+network namespace as uid/gid 10001 with **every capability dropped** (`CapEff = 0`), `NoNewPrivs = 1`, a **read-only image tree** and tmpfs over the three writable paths. Measured on this host: **PASS**, 12/12 Judge Kit gates inside the sandbox, and the 20 produced artifacts are identical in name to the host run. The run asserts each property before the command starts and records its scope in `docs/EVIDENCE/container-local-2026-11-22.json`.
   - What it still does **not** prove: that `docker build` succeeds, and that the Docker daemon's own hardening behaves identically to the namespace equivalent. `tools/offline_local_check.py` (the earlier namespace-level approximation, whose scope is recorded in `docs/EVIDENCE/offline-local-2026-11-22.json`) is superseded by the container-equivalent run. A maintainer with Docker and a registry should run `make docker-check` once locally to retire this limitation entirely.
10. **L10 — Organisational Independence Is Still Unevidenced (`Q-ORG-01`, `Q-ORG-02`):** the verifier was not authored by a separate human or agent context. The *technical* separation is real and machine-checked (AST + runtime file-open spy; a from-scratch re-derivation in `independent_verifier/` reproduces every committed episode signature-identically and all official `D01..D20` truths at F1 = 1, FP = FN = 0), but the *organisational* separation is not, and no AI agent may close that question. See `docs/INDEPENDENCE.md`.
11. **L11 — The Image Is Reproducible for Its Base, Not for Its Debian Package Versions (`D-18-02`, TZ §22.4):** the base image is pinned **by digest** (`python:3.11-slim-bookworm@sha256:a36c24f9cbdf4fd0f52d67f0823eeac19c2028c637cecc392d97f980d4fec56b`, the multi-platform `linux/amd64` + `linux/arm64` manifest of CPython 3.11.16 on Debian bookworm), so the userland, the Python patch version and the OS do not move under the release. The two Debian packages the image installs (`make`, `util-linux`) are, however, resolved by `apt` **at build time** from the pinned base's configured Debian mirrors:
   - vendoring the `.deb` files is not permitted (TZ §22.3), and
   - pinning an exact package version would break the build for every future consumer as soon as the mirror drops that version — a strictly worse failure mode than a recorded drift.

   The versions actually installed are therefore **recorded, not pinned**: the image writes them into `/usr/local/share/twinledger/build_info.json`, the CI job `docker-offline` publishes that record on every run, and the CI job `base-image` reports whether the upstream tag has moved away from the pinned digest. `docs/EVIDENCE/docker-build-info.json` records the pinned facts (base image, digest, Python patch version, declared packages); the resolved package versions are the part of the environment that can still change, and CI says so out loud instead of hiding it.
