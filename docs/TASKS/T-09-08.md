# T-09-08 — Phase 9 task 9.8: Add platform-specific isolation profile

- **Phase:** 9 (ПРОЦЕССЫ, SEALED EVALUATION И RECEIPTS)
- **Status:** DONE
- **Requirements:** REQ-SEAL-001..005, P-012, Risk R-09
- **Owner:** Zone 2 (`harness/sandbox.py`, `docs/THREAT_MODEL.md`, `docs/LIMITATIONS.md`)
- **Dependencies:** Task 9.2

## Goal

Enforce defence-in-depth POSIX subprocess hardening and emit an explicit, non-exaggerated `SecurityProfile` documenting active vs unavailable OS isolation controls.

## Acceptance criteria

- `harness/sandbox.py` enforces separate OS processes, post-termination scorer barrier, empty read-only `policy` scratch `cwd`, staged read-only `public/` (`0o444`/`0o555`) without `sealed/`, `close_fds=True`, sanitized environment allowlist, fixed `argv` (`shell=False`), and best-effort POSIX `RLIMIT_CPU`/`RLIMIT_FSIZE`/`RLIMIT_NOFILE`.
- `SecurityProfile.is_full_os_sandbox` is explicitly `False` (`host-posix-subprocess-v1` / `container-posix-subprocess-v1`), recording `unavailable_controls` (`container_mount_namespace`, `container_network_disabled_flag`, `seccomp_bpf_syscall_filter`) per Master TZ Principle P-012 and Risk R-09.
- Verified with canary injection and adversarial policy probes in `tests/security/test_phase09_isolation.py`.
