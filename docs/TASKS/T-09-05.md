# T-09-05 — Phase 9 task 9.5: Add trajectory hash chain

- **Phase:** 9 (ПРОЦЕССЫ, SEALED EVALUATION И RECEIPTS)
- **Status:** DONE
- **Requirements:** REQ-SEAL-021, REQ-CONTRACT-010
- **Owner:** Zone 2 (`seal/hashchain.py`, `harness/trajectory.py`)
- **Dependencies:** Phase 1 frozen `trajectory_event.schema.json` v1.0.0

## Goal

Bind every episode interaction (`reset`, `tool_call`, `submit`, `terminate`, `error`) into a deterministic SHA-256 hash chain anchored at `truth_commitment` and `episode_id` with zero wall-clock fields.

## Acceptance criteria

- Normative domain-separated formula implemented identically in `seal/hashchain.py` and `harness/trajectory.py`:
  - `h_0 = SHA256("twinledger:h0:v1|" + truth_commitment + "|" + episode_id)`
  - `h_{i+1} = SHA256(b"twinledger:event:v1|" + h_i + b"|" + canonical_bytes(event_i))`
- Every emitted event validates against frozen `contracts/trajectory_event.schema.json` v1.0.0; wall-clock keys are rejected.
- Any payload, order, or length mutation alters `trajectory_head` and fails `verify_hash_chain`.
- Tested in `tests/seal/test_hashchain.py` and `tests/unit/test_property.py`.
