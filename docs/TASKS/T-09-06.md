# T-09-06 — Phase 9 task 9.6: Add Merkle tree and receipt

- **Phase:** 9 (ПРОЦЕССЫ, SEALED EVALUATION И RECEIPTS)
- **Status:** DONE
- **Requirements:** REQ-PROD-006, REQ-SEAL-020, REQ-SEAL-022, REQ-SEAL-023
- **Owner:** Zone 2 (`seal/merkle.py`, `seal/receipt.py`, `seal/cli.py`)
- **Dependencies:** Phase 1 frozen `receipt.schema.json` v1.0.0, Tasks 9.4–9.5

## Goal

Implement domain-separated binary Merkle trees, batch receipt sealing, and offline receipt verification (`python3 -m seal.cli verify-receipt`).

## Acceptance criteria

- `seal/merkle.py` implements domain-separated leaves (`0x00`), internal nodes (`0x01`), size-bound root (`0x02 || uint64_be(leaf_count) || top_node`), and RFC-6962 odd-leaf promotion without self-duplication (`CVE-2012-2459` safe).
- `seal/receipt.py` constructs `receipt.schema.json`-valid receipts with `lineage` digests (`generator_version`, `config_hash`, `public_manifest_hash`, `truth_commitment`, `trajectory_head`), `seal_receipt_batch`, and `verify_receipt_offline`.
- `seal/cli.py` provides offline `verify-receipt`, `verify-commitment`, and `verify-chain` commands.
- Tested across tree sizes `0..25` and tampered proofs in `tests/seal/test_merkle_and_receipt.py`.
