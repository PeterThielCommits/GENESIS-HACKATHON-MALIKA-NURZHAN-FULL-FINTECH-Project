# GIT AND DATA POLICY

Decision: **D-0008**. Requirement: REQ-DATA-022, REQ-GH-007, REQ-SEAL-012.

## 1. Rule

| Category | Committed? | Where | Why |
|----------|-----------|-------|-----|
| Public episode data (`public/`) | **No** (generated) | `episodes/<id>/public/` – ignored | regeneration is deterministic; committing thousands of rows bloats the repo and invites accidental truth inclusion |
| Sealed truth (`sealed/truth.json`, `sealed/provenance.json`) | **Never** | `episodes/<id>/sealed/` – ignored | answer key |
| Salt / seed material (`*.salt`, `*.seed`, `sealed/`) | **Never** | anywhere – ignored | secrecy of the commitment |
| Held-out episodes (`episodes/hidden/`) | **Never** | ignored | benchmark integrity |
| Train/dev episodes | **No** for now | `episodes/train/`, `episodes/dev/` – ignored | they are reproducible; publishing dev is a later, deliberate decision with a CR |
| Episode manifests (hashes only) | **Yes** | `episodes/manifests/*.json` | provenance without answers |
| Golden digests (hashes only) | **Yes** | `episodes/manifests/golden/*.json` | reproducibility proof |
| Tiny hand-authored fixtures | **Yes** | `contracts/fixtures/`, `tests/fixtures/` | contract tests need fixed bytes; they contain no real data and no live salt |
| Test salts | **Yes**, labelled | fixture JSON with `"salt_mode": "TEST_FIXTURE"` | REQ-SEAL-013: a fixture salt is a test constant, never a benchmark secret |
| Generated reports | **No** | `artifacts/` – ignored | regenerated by `make verify`; a stale report must never masquerade as current |
| Logs | **No** | `*.log` – ignored | may contain paths or seeds |
| Third-party wheels | **Only with a CR** | `vendor/` | licence and hash review (Q-011) |

## 2. Enforcement

* `.gitignore` covers every "No"/"Never" row; `tools/check_governance.py` check `GOV-GIT-01`
  fails `make verify` if a pattern disappears, and the test
  `tests/phase0/test_git_data_policy.py` additionally asserts that no tracked path matches a
  sealed pattern.
* `tools/check_governance.py` check `GOV-CLAIMS-01` scans committed text for literal
  `salt`/`master_seed` values (16+ hex chars) and fails as a **release blocker** (exit code 4).
* Reviewers must confirm that no `episodes/**/sealed` or `artifacts/` path is added to a
  commit; `git status --ignored` is part of the phase checklist.

## 3. Reproducing an episode without committing it

```
python -m gen.build_episodes --config configs/generator/default.json --split dev
# writes episodes/<id>/{public,sealed,manifest.json}
python -m tools.verify_manifest episodes/<id>/manifest.json
```

The published manifest proves *which* bytes existed (hashes) without publishing them, and the
golden digest file lets a third party regenerate and compare.

## 4. Test-only salt mode

A fixture may contain a salt when `salt_mode == "TEST_FIXTURE"`. Such a salt is a constant
used to make a unit test deterministic; it is **not** protection for a live benchmark and it
is never used to generate an episode that could be scored. Production `CLOSED_EVAL` runs use
a cryptographically secure salt from `secrets.token_bytes(32)` held only in `sealed/`.

## 5. What changes require a CR

* committing any dev/train episode,
* publishing a golden digest that reveals structure (e.g. per-row hashes),
* vendoring wheels,
* any change to the sealed directory layout (it is part of the receipt contract).
